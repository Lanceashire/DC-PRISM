# 新实验整合决策

## 本次目标与来源权重

新实验以提供的 DC-PRISM 源码为主线，形成独立仓库。旧 LexiRiskLabel 只作为方法来源、历史机制解释和代码参照。本次不把旧仓库阶段门槛移植到新项目，也不要求新实验重复旧 M1–M5/E0–E3。用户在本次工作中明确了这一范围。

输入包含五份明确点名 ZIP、一份整合报告和两段指定聊天。完整聊天读取结果都只有五轮且返回无更早分页；工具没有提供聊天中所有历史附件或 sandbox 下载文件的真实内容，因此只把已读消息视为审查线索。六个明确提供的本地文件均读取并计算了来源记录。聊天里提及而本次没有明确提供的 RealData 包，没有擅自加入活动源码。

文件名后缀不能证明版本顺序。使用本地 birth/mtime/ctime、ZIP 成员时间、变更日志、源码差异、NPZ 哈希及实际 seed/method 覆盖共同核对。ZIP 时间没有时区；本地文件创建和修改时间带 +08:00，二者不混用。详细记录在 `provenance/input_file_properties.json`。

## 两段聊天如何合并

《输出实验数据集》讨论了较早返修包的剩余任务，包括 D0-only、16 seeds、World D 真概率、有限候选族 Oracle、来源说明、统计和负结果。后来的提交包已经实现了其中多项，不把旧待办无条件继续列为缺陷。

《解释新算法机制》继续审查更晚提交物，区分主指标 ALC 与末轮指标，提出排序、释放时序和快速复现覆盖问题。其“当前 NumPy 环境不匹配归档”的观察具有环境前提。本次取得锁定 NumPy 2.1.3，并完整重跑 P4 后得到 6,400 行逐项一致，因此将候选池问题更新为跨版本确定性风险，而非提交版在原环境不可复现。聊天中关于最强基线与统计的数值仍须以具体版本 CSV 为准。

两段聊天的审稿建议没有自动转化为本次的执行授权或新注册协议。相互矛盾的说法由实测源码与产物决定。本次修复建立 `dc-prism-integration-v1`，保留原包，使用原 seed 作修复再运行，不声称获得全新独立确认。

## 整合报告和早期升级包的位置

整合报告提供了有用的研究问题：何时组成收益超过数量损失，何时风险保护只是保守少选的结果。保留这一问题和同状态分账视角，但报告的 I0–I4 是当时的建议矩阵，不是当前项目必须逐项重做的命令。后来的源码已加入 Pending-aware 矩阵集合效用、数量惩罚和经验分位数 Gate，不能再写成尚未接入 PA。

早期 CC-LRBE 包的 FAVE 名称沿用但公式改变，IPW 用确定性选集比例代替真实倾向概率；风险前缀搜索也不是一般组合优化精确解。最新版 DC-PRISM 并未使用这份伪 IPW，因此这些属于早期分支风险，不作为最新版仍存在的 IPW 缺陷。早期源码保留为开发参考，不接入活动管线。

旧仓库固定在 `b4f3f2db6788bb8c7bb127a209e4f518fbafe226`；保留原冻结 FAVE 参考，避免把不同信息效用都叫原方法无损升级。新核心的 Fisher Pending-aware 实现有自己的身份。`Orig-PA` 是新包中的局部静态贪心适配，不能声称逐位重现旧仓库完整 PA。

## 本次实际整合内容

活动目录来自最新提交物，仅针对已证实的实现和运行缺陷修复：当轮在线评价只使用已释放标签；显式全局 ID 处理候选同分；小池固定数量精确枚举；大池提供可行参照回退；固定 ε 达到登记数量；运行目录隔离和失败清单；增加动态因果时序与预算验证。λ、Gate 阈值、后验曲率系数不因结果调参。

固定 ε 的整数规则在新协议中明确为 `ceil((1-eps)*K_reference)`。旧包采用 `round`，单独看 `round` 并非数学错误；这里是显式协议对齐。旧实现即使按自身 `round` 目标也有 362/640 条 P4 记录未达目标，这是独立的已证实缺陷。所有改变均通过新协议、源码哈希和新结果目录追踪。

原 P2 受控结果与负 cell 保留；没有为了改善显著性重新调参或追加确认世界。本次也没有将修复后的 P4 成绩替换进原归档，或将旧 P2 自动认证成修复后各消融的证据。

## 后续研究焦点

先按修复后的统一时间定义解释 P4，并检查 DC 与风险参照、信息采集适配基线的配对差异。下一步科学问题是受控 P2 与真实回放的差异来自信息代理、数量机会成本、概率错设还是风险可行域。只有要作严格模块归因时，才增加共候选族、共权重与共计算预算的单因素消融。

已有四个数据集及 seed 已参与设计与审查。新外部优越性主张需要新的合格队列和事前协议，不能单靠这些 seed 的修复重跑建立。若真实数据结果有限，报告边界；不把“所有数据集获胜”设为程序验收条件。

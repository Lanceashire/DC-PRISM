# 审稿意见（严格审稿人视角，第二轮）

**稿件**：The Oracle Gap Has a Floor: Separating Aleatoric and Deployable Headroom in Evaluating Label Acquisition
**设定的投稿去处**：DASFAA 2027 研究轨，或 ECML-PKDD
**总体建议**：Borderline，偏 weak accept（3/5）；置信度 4/5

---

## 一、概述
论文指出，主动学习基准里常用的 oracle 上界（贪心 oracle、best-of-strategies）依据实现标签挑选样本，所以它报告的"领先"混入了两样东西：测试集复用，以及由标签随机性造成的偶然性下限。作者把报告差距拆成测试集复用、偶然性下限和可部署差距三部分，并用在不相交记录上拟合的 p̂ 在真实数据上估计。主要发现包括：
- 下限占比随标签噪声上升，8–9 个数据集上 Spearman 相关为 0.83 / 0.67；
- 两领先者闭式下界与独立正态上界在 87 个设定中都包住了实测下限；
- 下限随风险预算升高；
- 能否拿到可部署差距，取决于信息代理与学习器是否匹配。

## 二、优点
1. **问题切中要害且及时**。近期 CDALBench、BoSS 用 oracle 差距论证"现有策略还有很大空间"，本文给出了一个具体、可检验的反思角度。
2. **结论有边界**。在低噪声的原始像素 USPS 上，作者承认 oracle 领先大部分是真实的；没有一概否定前人，这一点难得。
3. **实证非常严谨**：全部预注册并冻结代码，有功效分析和同时区间；三种学习器、八个数据集；有已知真值时的验证和对真实结果的校准；失败结果（PPDai 在 MLP 下的校准）也如实报告。
4. **可复现性强**：表格和图都由脚本从结果文件生成。

## 三、主要问题（Major）

### M1. "可部署差距"的估计器偏弱，"假象占比"可能被系统性高估
可部署差距是用"事前贪心 oracle"度量的，作者也承认它只给出下界。但从数据看，这个下界非常松：
- 表 1 半合成数据这一行，报告差距 7.2 中可部署部分只有 0.3，校正后的领先变成 0.0，也就是说事前 oracle 并不比最好的固定策略更好。
- 我核对了结果文件：半合成数据上，事前贪心 oracle 在 **72% 的状态里不如最好的实用策略**；真实标签上是 54%。一个号称"可部署上界"的估计器连实用策略都打不过，说明它远没有达到可部署的最优。

所以"58–100% 是假象"这个头条数字，有相当部分可能来自估计器太弱，而不是 oracle 差距真的不可达。**要求**：
- 至少把"事前 oracle"换成"事前 oracle 与所有实用策略中的最大者"，作为可部署差距的下界；
- 或者用更强的事前搜索（多起点、交换步、集合族上的穷举）；
- 正文主要数字改用这个更紧的口径。

### M2. 真实标签上的 oracle 差距，并不是基准会报告的那个差距
在真实标签状态中，贪心 oracle 用的训练标签是从 p̂ **重抽**出来的，并不是记录下来的真实训练标签。也就是说，"报告差距"、"事后差距"本身就是基于 p̂ 的模拟量。
- 作者只对族 oracle 的 H_post 做了"与实现结果吻合"的校准，**没有对贪心 oracle 的三部分分解做任何真实标签上的检验**。
- 基准论文报告的是在一组真实标签上跑一次 oracle 的结果。论文应当至少报告：用真实记录标签跑贪心 oracle 得到的报告差距，与用 p̂ 估计的报告差距是否一致（就像 H_post 的校准那样）。
- MLP 下 PPDai 的 H_post 校准已经失败（7.4 对 5.0），这说明 p̂ 带来的偏差不可忽视，而贪心 oracle 的分解对 p̂ 可能更敏感。

### M3. 闭式上下界的"100% 覆盖"在很大程度上是机械成立的
- 下界 F_two 只考虑两个领先集合，对实测下限天然就是下界（只差正态近似和估计误差）。
- 上界 F_ind 假设各集合相互独立，从 Fig. 2a 看，它通常比实测值大 3–10 倍，非常松。
- 因此"87/87 包住"几乎不提供信息；真正有预测力的是"实测 ≈ 2.7 × F_two"这个**经验**比例，而它没有理论推导，因子 2.7 在不同学习器、族大小下是否稳定也没有分析（Fig. 2a 显示有明显离散）。
- **要求**：把"可预测"降格表述为"由一个可计算的量所刻画"；给出比例因子随候选族大小、学习器变化的分析，或推导一个更紧的上界，比如考虑相关性的多领先者近似。

### M4. 外推到真实主动学习预算的依据不足
- 实验中每个状态只有约 100 个训练样本、24 个候选、每轮约 6 个标签。CDALBench、BoSS 的设定是数百到数千个标签、大型模型和大批量。
- 论文说下限"随获取的随机结果数量增加"（预算杠杆），但训练集变大时，单个标签对模型的影响会下降，s 可能随之减小。规模变大以后，下限占比是升还是降，并没有被检验。
- 原始像素 USPS 加 MLP 是唯一接近基准的设定，而它的结论恰恰是"oracle 领先大部分真实"。这削弱了论文对主动学习评价的整体警示意义。
- **要求**：至少做一组规模扩展（例如 USPS 或 Bank Marketing 上把训练集和预算扩大 5–10 倍），报告下限占比的变化趋势；或者在摘要和引言里明确把结论限定在"小预算、结果带噪声的决策场景"。

### M5. 噪声梯度的证据太薄，"噪声指标"的定义也有混淆
- 只有 8–9 个数据集，Spearman 0.83（p≈0.01）和 0.67（p≈0.05），其中 MLP 下已经在显著性边缘。
- 噪声指标 mean p̂(1−p̂) 把**类别不平衡**和**不可约噪声**混在一起：例如 Bank Marketing 正例率只有 12%，所以 p̂(1−p̂) 低，但它的预测难度并不低。
- USPS、Spambase 的"低噪声"在很大程度上是作者自己的预处理造成的：二分类方式和是否降到 10 个主成分都会改变噪声。原始像素版和 10 主成分版噪声不同就说明了这一点。
- **要求**：报告更多数据集，或者在同一数据集上**人为注入可控的标签噪声**（如翻转率 0–30%），给出一条连续的剂量—反应曲线。这能更直接地支撑"下限随噪声上升"的因果解释。

### M6. 风险约束与 DC-PRISM 部分像是另一篇论文
- 风险包络、数量参照、待反馈信息、DC-PRISM 的细节占了相当篇幅，但核心贡献（oracle 差距的分解）并不依赖风险约束。
- "下限随风险预算升高"的机制，作者自己解释为"获取的标签更多"，而不是"风险本身"。那么它与风险约束的关系只是间接的：换成普通的标签数量预算也会得到同样的结论。
- DC-PRISM 一节和延迟回放一节对主线的贡献有限，读者会疑惑这篇论文到底是评价方法论文还是风险约束获取论文。
- **建议**：大幅压缩 DC-PRISM 和回放部分，放到附录；或者把"风险约束"讲成一个能独立改变结论的维度（例如在相同标签数量下比较不同风险结构），否则就降级为应用背景。

## 四、次要问题（Minor）
1. **摘要里"58–100%"包含了超过 100% 的情况**：再入院数据上可部署领先为负（−0.1），应解释或改为"约 60% 至全部"。
2. **表 2 原始像素 USPS 这一行没有逻辑回归的结果**，需要说明原因（只在 MLP 研究中使用）。
3. **"material"阈值 5×10⁻⁴ Brier 的实际意义没有说明**：建议报告对应的 AUC 或决策层面（如违约损失）的变化，说明这个量级值得关心。
4. **F_two 依赖 D 服从正态的假设**，这一假设在小样本、二元结果下是否合理，应给出诊断（例如 D 的偏度分布）。
5. **贪心 oracle 有一个停止规则**（没有改进就停），它和 CDALBench 原本的规则（回退到 margin sampling）不同，应说明差异，以及对报告差距的影响。
6. **记号负担重**：H_post、H_pre、F、F_two、F_ind、Γ_π、q、R_α、M_K 等同时出现，建议加一张记号表或精简。
7. **框架图信息量偏大**：在单栏版式里字仍然偏小。④ 号面板中"代理与学习器匹配"的韦恩图含义不够直观。
8. **相关工作缺少两条线**："主动学习中的标签噪声"（如带噪声 oracle 的主动学习）和"数据估值 / 子集选择中的 oracle 子集"。
9. **"Readmission"写法不统一**：正文、表格和数据描述中出现了不同叫法，应统一。

## 五、给作者的问题
1. 把可部署差距的下界取为"事前 oracle 与所有实用策略中的最大者"以后，表 1 和表 2 的假象占比分别是多少？
2. 用真实记录的训练标签跑一次贪心 oracle，得到的报告差距和事后差距，与 p̂ 重抽得到的估计是否一致？
3. 在训练集扩大 5–10 倍的设定下，下限占比如何变化？
4. 在同一数据集上注入可控的标签噪声，下限占比是否随噪声单调上升？
5. 2.7 这个比例因子是否有理论来源？它在不同族大小、学习器下的离散程度如何？

## 六、总结
这是一篇问题意识清楚、实证非常严谨的评价方法论文，指出了主动学习 oracle 上界中一个确实存在、此前没有被量化的偏差，并诚实地给出了适用边界。主要短板在于：
- 用来度量可部署差距的估计器明显偏弱，导致头条的"假象占比"可能被高估（M1）；
- 真实标签上的 oracle 分解没有经过实现结果的校验（M2）；
- 闭式上下界的"100% 覆盖"信息量有限（M3）；
- 结论能否外推到真实规模的主动学习预算尚不清楚（M4）。

若能补上 M1、M2 并在 M4 上给出至少一组规模扩展，我会把评分提高到 weak accept（3.5–4/5）。以当前形式，属于 borderline。
